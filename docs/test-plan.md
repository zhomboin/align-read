# AlignRead 回归与发布验收

验收覆盖产品需求中的 AC-01～AC-16、AC-P1-01、AC-P1-03 和 AC-P1-05。自动化运行生产构建中的双栏、原位和选词翻译，以及 Popup、Options 和 Worker。Chromium 渲染测试页面，翻译服务与扩展所需的 Chrome API 使用可控响应。 [验收要求](AlignRead_PRD_v1.1.md#12-验收标准与测试用例)

## 运行

在 `alignread-extension/` 目录执行。默认从 PATH 查找 `chromium`，也可用 `CHROMIUM_BIN` 指定本机 Chromium 或 Chrome 的可执行文件。

在 WSL 中运行测试时，可将 `CHROMIUM_BIN` 指向 Linux 版浏览器。如果已经安装 Playwright 的 Chromium Headless Shell，可用 `find ~/.cache/ms-playwright -type f -name chrome-headless-shell` 查找路径，再用 `CHROMIUM_BIN=/实际路径/chrome-headless-shell npm run test:release` 执行。浏览器提前退出时，测试会输出进程状态和浏览器诊断信息。

```bash
npm ci
npm run check
npm run build
npm run test:release
npm run zip
```

改动设置界面或 AI 翻译时，构建后运行 `npm run test:settings`。改动选词翻译时，构建后运行 `npm run test:selection`。改动双栏提取或显示时，构建后运行 `npm run test:layout`。改动原位翻译时，构建后运行 `npm run test:replace`。改动 SPA 动态更新或站内导航时，构建后运行 `npm run test:spa`。

向 `main` 发起 PR 或推送到 `main` 时，[GitHub Actions 工作流](../.github/workflows/regression.yml) 自动安装锁定依赖，做类型检查、构建、完整回归和 ZIP 完整性检查。

测试使用模拟翻译响应。控制台列出样本从开启到工具栏可见及全部模拟译文渲染完成的耗时，供同一环境回归比较。

## 自动化覆盖

| 验收编号 | 测试行为 |
| --- | --- |
| AC-01、AC-07 | 检查整页模式的侧栏和正文位置、仅正文的导航排除，以及标题、列表、引用、代码和表格。样本包含普通文章、文档目录、固定目录、右侧目录和 Markdown 常用结构。 |
| AC-02 | 使用分隔条方向键把原文栏由 50% 调到 40%，检查左栏像素宽度与后台保存比例，再按保存值重新开启。 |
| AC-03、AC-04 | 对重复文本的第二处悬停、直接点击译文及按 Enter，检查定位到正确原文。检查段末没有「原文」按钮，以及链接和译文选区的操作。 |
| AC-05、AC-06 | 分别从原文和译文滚动，验证另一侧跟随。检查固定目录、锚点、折叠控件、文本选区、页脚自然流动、Cookie 按钮和关闭后的布局恢复。 |
| AC-08、AC-15 | 模拟部分段落缺失、服务限流和鉴权失败，检查可用译文、失败项重试、未配置状态和连接测试结果。 |
| 设置界面 | 检查弹窗宽度、白色背景与表单、设置入口、已配置服务列表和切换。检查切换时旧会话结束、待授权服务被阻止翻译、所选服务持久保存。检查独立设置页白底、服务下拉框与表单联动、单独启用所选服务、桌面和窄屏布局、服务授权和连接状态、翻译范围滑块的选择与保存、键盘调节栏宽及恢复默认。 |
| AI 翻译 | 验证端点校验、单域名授权、密钥隔离、连接状态、双栏乱序回填和选词翻译。逐项检查官方预设的接口、模型参数、独立授权、双栏和选词请求，以及豆包推理接入点设置。检查 DeepSeek JSON 请求、MiniMax 分站授权、慢速流拼接、推理内容分离，以及首次响应、无数据和总时长超时。模拟截断、缺失、重复和未知序号、鉴权失败、限流及权限撤销。 |
| AC-09、AC-10、AC-11、AC-16 | 模拟延迟响应中关闭、离开页面和连续十轮开关。用不同标签和文档 ID 检查后台授权隔离、旧任务取消，以及迟到请求被拒绝。 |
| AC-12、AC-13、AC-14 | 检查未授权时阻止翻译，过滤输入框、密码、文本域、可编辑和隐藏内容，检查内部页、PDF、注入失败及窄窗口的拒绝路径。 |
| AC-P1-01 | 检查普通网页和双栏原文中的鼠标、键盘触发，加载、复制、重试、关闭和选区保留。覆盖双栏和选词的两种开启顺序、空闲脚本复用、卡片与右栏重叠时的按钮点击，以及未授权、禁用站点、敏感页确认、表单或隐藏内容、过长选区、取消及迟到响应。 |
| AC-P1-03 | 检查弹窗滑块点击与方向键选择、翻译范围传递，以及从译文工具栏切到原位、从浮条切回双栏。检查窄窗口提示及译文保留、保护区域、站点文本更新、重试、恢复原文和迟到结果。 |
| AC-P1-05 | 模拟同页正文增删改、可见性变化、标签切换与暂停，核对未变段落保留译文及新段落定位。检查原页重建 `body` 或移除分栏宿主、样式表时，双栏会话能恢复并继续翻译。验证 CSS 面板、普通锚点、查询参数、站内路由、旧批次取消、迟到响应隔离、敏感页面授权和关闭清理。 |

### 译文样式覆盖

| 原页表现 | 译文验收 |
| --- | --- |
| 卡片网格、正文侧栏、多列页脚 | 保留横向分组和顺序。缩窄时卡片换行，固定提示条与原页交互保持可用。 |
| 横排链接、链接型和 ARIA Tab、网格列表 | 保留排列和可识别的选中态。Tab 在窄栏内横向滚动，普通列表保留项目符号、编号和嵌套。 |
| 页头导航、嵌套标签和仓库页签 | 导航和标签按内容宽度排列，保留原页分组、顺序和标签外观。缩窄时导航与标签按需换行，页签可在自身区域横向滚动，选中项仍可辨认。 |
| 新闻条 | 标签、分隔符和链接横排并保留对齐、配色及链接目标。窄栏中链接文字换行，标签仍可定位原文。原页分行的链接沿用常规布局。 |
| 文件列表和源码预览 | 保留文件行、链接、大小、提交信息和时间的列结构。目录行留出空白大小列，长文件名在窄栏内换行。可见代码保留缩进和空行。收起的菜单及代码均不送译。 |
| 代码保护 | 检查双栏和原位翻译对原生代码、标注为代码的内容及等宽预排版代码的处理。代码保持原文，普通等宽提交说明仍可翻译。仅有代码时，双栏显示原文且发送零批次。 |
| 提示框、引用、行内强调、键盘按键、上标和下标 | 保留可识别的背景、边框和文本强调。显式换行及 CSS 保留的换行不被翻译服务合并。 |
| 定义列表、分隔线、展开和折叠摘要 | 保留结构。展开或折叠后按当前可见状态更新，隐藏正文不送译。 |
| 图片、图注、宽表格和合并单元格 | 图片位置使用占位，图注可翻译。保留表头、跨度、对齐与表注位置，宽表只在自身区域横向滚动，定位时可滚出目标单元格。 |

普通文章、技术文档、项目产品页和 README 各保留一个真实样本，并在默认栏宽和窄译文栏各检查一次。背景图、复杂绘图、站点动画与动态组件另按原页能力核对。右栏重建可读结构和受支持的样式属性。

## 原位翻译验收

1. 构建后运行 `npm run test:replace`。检查默认双栏、页内往返切换、切换后重开弹窗、原位翻译的安全过滤、恢复、失败重试和站内导航。 [定向测试](development.md#提交与回归)
2. 在桌面 Chrome 打开测试网页，分别用「仅正文」和「整页可见文字」开启双栏。用译文工具栏切到「原位翻译」，再用右上角浮条切回「双栏对照」。核对语言、范围与服务沿用当前设置，切回后左栏显示原文。
3. 在原位翻译中把视口缩至 960 CSS px 以下，点选双栏，确认出现宽度提示，已显示的译文和原位模式保持可用。检查链接、行内样式、图片和页面控件仍可用，代码、编辑区和网页标记为不翻译的区域保留原文。
4. 在翻译中途点击浮条的「恢复原文」，确认迟到结果返回后页面仍显示原文。让页面先更新某处文字，再恢复原文，核对网站更新是否保留。
5. 开启选词翻译并选中原位译文，检查卡片是否使用当前选中的译文。 [选词翻译用法](../README.md#选词翻译)

## SPA 验收

1. 在 WSL 的扩展目录运行 `npm run check`、`npm run build` 和 `npm run test:spa`。测试使用本地页面与模拟翻译响应，覆盖 Chromium 中的双栏和 Worker。 [本地开发](development.md#提交与回归)
2. 在桌面 Chrome 的 `chrome://extensions` 加载当前工作树的生产构建。更新构建后点击「重新加载」，刷新已经打开的测试网页，再选用已授权的翻译服务开启双栏。
3. 在 Spring AI 项目页的 Overview 开启双栏，从左栏点 Learn，再点回 Overview。分别在 Overview 翻译仍在进行和已完成时操作。确认双栏保持开启，右栏移除旧面板内容并自动翻译新面板。用「整页可见文字」和「仅正文」各检查一次。 [Spring AI Overview](https://spring.io/projects/spring-ai#overview) · [Spring AI Learn](https://spring.io/projects/spring-ai#learn)
4. 在支持的单页应用里展开折叠区、加载更多正文，或通过筛选控件修改同文档的查询参数。查看右栏是否更新，未变段落的译文与定位是否仍正确。点击仅用于页内滚动的普通锚点，核对原页跳转与已有译文。
5. 打开切换到其他路径或哈希路由的站内链接，再用浏览器前进和后退，检查右栏清除旧译文并显示新正文。翻译中暂停后再切换页面，确认继续前不会发起新批次。关闭双栏或刷新，确认面板、高亮和分栏样式清理完毕。敏感路由的验证使用受控样本，确认重新授权前没有送译。

## 真实网页回归

在生产构建中选用已授权的服务。普通文章、Gradle User Manual、Spring Boot 项目页和包含列表、锚点及表格的 GitHub README 用作代表性样本。分别以整页与仅正文开启双栏，检查默认和较窄的译文栏、双向滚动、原页控件、点击译文定位和关闭恢复。在不同标签页并发开始翻译，刷新其中一页后检查另一页进度。 [Gradle User Manual](https://docs.gradle.org/current/userguide/part2_gradle_tasks.html)

记录实站的扩展版本、Chrome 版本、窗口宽度及页面 URL。验收真实翻译服务时，在设置页配置并授权该服务，运行「测试连接」，确认公开文章显示服务返回的真实译文，并记录 Provider 名称与结果。发布至少需要一个服务完成真实接口验收。

在 Spring 首页以整页模式开启双栏，找到首屏下方的新闻条，核对右栏的圆角标签、分隔符和链接是否居中同排。拖动分隔条缩窄译文栏，检查链接可读、可打开，并在文字较长时在行内换行。 [Spring 首页](https://spring.io/)

在 Hugging Face 文件页以整页模式开启双栏，检查页头导航、模型标签和页签是否按原页分组紧凑排列，当前页签是否可辨认。检查右栏逐行显示文件和提交信息。缩窄译文栏，检查导航和标签能换行、页签能在自身区域横向滚动，长文件名仍在所在列内。打开源码预览，检查代码缩进和空行。在原页打开和收起菜单，核对右栏随可见状态更新。 [文件列表](https://huggingface.co/MiniMaxAI/MiniMax-H3-Image/tree/main) · [源码预览](https://huggingface.co/MiniMaxAI/MiniMax-H3-Image/blob/main/model_index.json)

同一测试网页分别在普通页面和双栏原文选中短语。通过弹窗各走一遍「先开选词，再开双栏」和「先开双栏，再开选词」。触发「译」后核对所选文字、译文、复制结果与关闭行为。再检查刷新后停用，以及编辑区内选中文字时无翻译操作。

AI 服务使用公开网页和专用测试密钥，确认模型能翻译含换行的多个段落，且点击译文可定位到对应原文。再选择一句话检查译文及复制效果。验收记录仅保留服务和模型名称、步骤及结果。 [AI 翻译验证步骤](development.md#ai-翻译验证)

## 发布包检查

执行 `npm run zip` 后，核对 ZIP 根目录的 `manifest.json`、扩展版本、基础权限和可选域名。检查 `icons` 中每个路径都指向包内相应尺寸的 PNG，逐文件比对已通过回归的生产构建。商店素材、申报文案和送审步骤见 [上架材料](chrome-web-store.md)。
